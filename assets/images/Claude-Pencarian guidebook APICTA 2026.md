1. **Offline-first, sync-when-possible** — bidan desa/kader di daerah blank spot bisa input data lewat SMS/USSD atau aplikasi ringan yang menyimpan lokal lalu sync begitu ada sinyal (relevan karena BPS/topografi sulit adalah salah satu penyebab keterlambatan).

3. **Visibilitas kapasitas RS real-time** — dashboard ketersediaan bed/NICU/ruang operasi antar-RS rujukan dalam satu wilayah, supaya tidak ada kasus "muter-muter cari RS yang mau terima" (salah satu penyebab keterlambatan penanganan yang sering muncul di studi kasus).
4. **Jejak audit & feedback loop** — setiap rujukan tercatat end-to-end (waktu deteksi → rujuk → tiba → tindakan), datanya bisa dipakai Dinkes untuk evaluasi performa wilayah — ini yang jadi nilai tambah untuk pemda/Kemenkes.

### Kenapa ini cocok untuk kekuatan teknis kamu
- **BullMQ + Redis**: pas banget untuk job queue notifikasi rujukan (push ke RS tujuan, retry kalau gagal, eskalasi otomatis kalau RS pertama tidak respons dalam X menit).
- **Bun + Hono**: backend ringan cocok untuk API yang harus tetap responsif di infrastruktur daerah dengan resource terbatas.
- **Drizzle + PostgreSQL**: skema untuk data pasien, riwayat rujukan, dan kapasitas RS — perlu desain yang hati-hati soal privasi data kesehatan (UU PDP).
- **TanStack Start/Query**: dashboard real-time untuk RS dan Dinkes, dengan sync status yang jelas (pending/synced/failed) — penting untuk kasus offline-first.
